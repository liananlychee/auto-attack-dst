# Auto Attack

客户端模组，默认按住 **R** 自动寻找附近敌人，靠近到当前武器的攻击距离后攻击，观察出手阶段后交替小步靠近和远离目标。以关闭延迟补偿、平均 ping 不超过 140 ms 为设计目标，实际攻击冷却仍由服务器决定。

## 操作与设置

- **R**：像原版 F 一样寻找附近敌人，距离不够时自动靠近，并连续攻击与走位。**Ctrl + R** 沿用 Ctrl + F 的强制攻击选敌规则。松开停止后续操作；已经被服务器接受的攻击可能继续完成。
- **按键冲突**：模组攻击键与游戏原版攻击键不能相同。若想把模组键设为 F，请先在游戏设置的控制页把原版攻击改成其他键，再设置模组按键。模组配置页有提示。
- **Esc → Auto Attack 手感设置**：打开手感面板，关闭后返回暂停菜单。界面沿用原版暂停菜单的卷曲边框、按钮、勾选框与菱形滑块。滑条支持拖动和点击定位，也可用两侧加减按钮微调；拖动松开时保存。
- **出手后停多久**：普通近战用于起步或重新对齐，连续阶段不逐击追加；其他武器每次出手后生效。可调 0～0.20 秒，默认约 0.07 秒。
- **每次走多远**：左边小步挪，右边迈大步。数值 0.2～2.0，默认 0.6；快走出攻击范围时会自动少走一点。
- 方向键或鼠标按住时，手动操作优先。每次出手后交替靠近与远离；远离时限制终点在当前估计的攻击范围内。冷却结束后直接尝试下一击，不等待走完整段距离；目标移动出范围时重新靠近；寻找和保留目标均使用原版 F 的选敌范围。目标消失、无有效目标或松开按键时停止模组发起的移动。

手感面板的手动等待和步长保存在本机 `auto_attack_settings_v1` 数据中，重新进游戏仍有效；旧自动辅助字段不再生效。模组配置页的数值是初始值；保存过的 手感面板数值优先。

## 算法

### 1. 按武器观察出手

`scripts/autoattack/weapons.lua` 集中定义已识别的普通攻击类型，攻击距离直接读取游戏的 `combat:GetAttackRangeWithWeapon()`，不使用统一的近战距离。支持长手长矛、鞭子、旺达警告表、亮茄法杖、冰火法杖、吹箭、回旋镖和弹弓的普通攻击；不自动释放右键法术、蓄力技能或特殊招式。

R 按下当帧尝试调用游戏的攻击入口，然后等待观察攻击动作，避免按请求时间直接倒数后撤。

关闭延迟补偿时，从角色同步回来的 `attack` 标记和已识别的攻击动画判断出手阶段：

| 普通攻击类型 | 保守出手等待 |
| --- | --- |
| 普通近战、女武神战矛、长矛、亮茄法杖、冰火法杖 | 按当前动画进度定位第 8 帧出手；未知动画长度回退到观察后等待 8 帧 |
| 鞭子、书本 | 10 帧 |
| 旺达警告表 | 按当前动画进度定位第 10 帧出手，不从收到动画时重新等 10 帧 |
| 吹箭 | 14 帧 |
| 回旋镖等普通投掷攻击 | 7 帧 |
| 弹弓 | 等实际 `slingshot` 射击动画到第 4 帧，兼容不同握柄的前摇 |

随后再加面板设置的等待。普通 `atk_pre` 为 6 帧，`atk` 的第 2 帧对应状态图第 8 帧出手；女武神三种战矛的普通攻击均使用该动作。长矛刺击、空手与工具攻击也分别校验其原版动画长度。警告表的两个前摇动画都是 8 帧，正式挥击动画第 2 帧对应状态图的第 10 帧出手。现在读取当前动画帧数，并计入画面上已经经过的等待时间；不再把收到动画当作前摇起点重新倒数。仅对长度匹配的原版动画启用该判断，动画长度未知或被修改时保留原来的保守等待。该优化减少收到动画后重复计算前摇的等待，不能改变服务器攻击冷却，也不能保证不同武器攻速相同。

这些值来自当前安装版本的状态图。法杖采用比部分投射物生成时间更晚的保守值；吹箭的快速连射若已错过安全走位窗口则跳过该步。弹弓缺弹、取消蓄力而未进入射击阶段时不走位。首次观察可能比真实起点晚，动画也不能证明服务器命中。

本机直接模拟或存在预测状态机时，普通动作等待 `abouttoattack` 标记消失；弹弓仍按射击动画判断，避免客户端前摇没有该标记而提前走位。未观察到攻击、动作取消或变成未知动画时跳过自动后撤；骑乘、变身及未知远程或特殊动画仅发起攻击。警告表动作进度以当前安装版本的 `wanda_attack.zip` 动画长度和 `SGwilson.lua` 第 10 帧执行攻击为依据，不当作命中确认。换武器会取消旧攻击对应的自动走位；投掷后正常脱手除外。每次请求都有超时，超时后跳过后撤，避免卡住或逐帧重发请求。

### 2. 连续请求与走位衔接

关闭延迟补偿时，`scripts/autoattack/remote.lua` 使用连续请求流程，参考本机 Happy Cheating 3.4（作者 07x23）按帧尝试攻击、穿插移动的节奏思路：

1. 首次按 R 用原版 F 的规则找敌人。服务器处理点地走位时会清空战斗目标，所以客户端保留刚刚选中的敌人。只要它还活着、可见、可攻击且在原版追击范围内，就按原版连续攻击的规则续打。目标死亡或离开范围后，按住 R 即可搜索下一只。切换 Ctrl 会重新选敌。
2. 靠近和追击使用原生攻击请求。走位后从下一个更新开始带上目标请求下一击，观察到新挥击就停止重复发送。松开 R 会释放模组的攻击控制。
3. 普通近战首次出手后按手动等待起步。连续攻击时，两步之间以 12 帧为目标间隔。如果游戏报告的最小攻击周期更长，就按它安排走位。
4. 每一步还要确认这一击的已知动画到了出手帧。定时已到但角色还在抬手，就延到出手后的第一个可用更新。每次挥击最多走一步。动画进度未知时回到逐击判断。
5. 手动移动优先。聊天、暂停和松开 R 会结束连打。游戏暂时禁用角色控制时暂停发招，如果一直按着 R，恢复控制后会接着打。特殊武器保留各自的出手判断和每击等待。

该流程不改变服务器攻击冷却。请求数量会多于实际出手数，这是重试机制；不代表每个请求都造成伤害。预测移动或本机直接模拟仍使用原有的动作观察路径。

### 3. 手动等待与固定超时

模组不读取 ping，不采样平均延迟或变化，也不自动追加等待。出手后的额外等待只取面板中手动设置的 0～6 帧（约 0～0.20 秒），默认 2 帧。普通近战将该值用于起步或重新对齐；进入固定节拍后不逐击追加。其他武器每轮开始时固定本轮值，避免动作中途改变等待。

旧本地存储或模组配置中的自动辅助值会被忽略；下次保存设置只写入手动等待和步长。未观察到动作的超时保护固定为 1 秒，预测路径的靠近重发间隔固定为 0.3 秒，均不根据网络延迟变化。

### 4. 交替走位

第一击出手后靠近，第二击出手后远离，之后交替。换目标或重新按 R 时从靠近开始。距离设置为每步上限：靠近时不穿过目标，远离时把终点限制在当前估计的攻击范围内，并保留 0.15 个单位余量。无法迈出有意义的小步时跳过该步。

不等待走到终点才攻击，游戏允许且目标在范围内时就发起下一击。目标移动造成脱离范围时，使用原版选敌校验保留目标；非预测模式通过原生攻击请求靠近，预测模式保留原来的移动处理。首次发现的范围外敌人也会靠近。关闭预测时通过原生非预测 WALKTO 回调发送移动；松开 R 时尝试取消模组发起的移动，手动操作优先。

该设计减少主动退远和等待走完造成的停顿，但不能保证命中、躲避敌人攻击或不同服务器上的相同攻速。

## 本地诊断

每次松开攻击键时，若本轮发出过攻击请求，客户端日志输出一行 `[Auto Attack]` 汇总：请求数、观察到的动作数、移动请求数、超时数、最大请求间隔、最大观察到的攻击间隔、重试数量、实际控制路径（`mode=rpc` 或 `mode=state`）、固定节拍帧数、跳过走位次数和重新对齐次数。不会逐帧写日志。请求间隔包含手动操作或无目标造成的等待，不代表服务器真实攻速。

当前版本 `1.0.15` 的模拟覆盖火腿棒、女武神战矛、漏掉一次客户端更新、攻击动画晚到、走位时目标被清空、击杀后换目标，以及暂时不能操作时按住或松开 R。实服的移动与命中效果仍需进世界验证。
